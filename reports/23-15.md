## 3. 계획서당 $20이 걸리는 곳 — 같은 틀에 하루 상한이 이미 들어 있습니다

`server/ai-usage.js`의 `budgetRefusal()` 하나입니다. 네 엔드포인트 모두
**OpenAI를 부르기 전에** 이 함수를 지납니다.

```
capsOf(env)
  proposalCostUsd   20         (AI_PROPOSAL_COST_CAP_USD)
  proposalTokens    2,000,000  (AI_PROPOSAL_TOKEN_CAP)
  userDailyTokens   6,000,000  (AI_USER_DAILY_TOKEN_CAP)
  warnRatio         0.7
```

막히면 403 + `capReached: true` + `budget`을 돌려줍니다.

**구멍 셋**

1. ~~단가가 없어 비용 상한이 죽어 있습니다.~~ **정정: 단가는 있습니다.**
   `wrangler.toml`의 `[vars]`에 입력 5.0 / 캐시 0.5 / 출력 30.0이 들어 있어
   `priced`가 참이고 계획서당 $20 상한이 실제로 걸립니다. 다만 **단가를 넣기 전에 쌓인 기록은
   비용 0으로 남아 있습니다** — 옛 기록으로 계산한 총액은 실제보다 작게 나옵니다.
2. **하루 상한에는 돈 기준이 없습니다.** `budgetRefusal`이 `userDailySpend`를 불러
   비용까지 받아 놓고도 `caps.userDailyTokens`만 견줍니다. 넣는다면 `capsOf`에
   변수 하나(`AI_USER_DAILY_COST_CAP_USD`)를 더하면 되고 **DB 변경은 없습니다.**
3. **계획서 식별자가 없는 호출은 계획서 상한을 안 받습니다** — `ocr`이 그렇습니다
   (`proposalId: ''`). 하루 상한만 받습니다.

## 4. 상한에 닿았을 때 지금 무엇이 보이나 — 「AI 실패」로 보입니다

**`capReached`를 읽는 자리가 `src/`에 한 곳도 없습니다.**
403의 메시지는 일반 오류 통로로 흘러 「AI 정밀 사업설계를 실행하지 못했습니다. …」로 감싸이고
로컬 분석으로 대체됩니다. 사용자는 **돈 때문에 멈춘 줄 모릅니다.**
§3(화면 밖에 버리지 마라)에 어긋납니다.

관리자 화면도 「계획서 1건 상한」만 보이고 **계정 하루 상한은 보이지 않습니다.**

### 무엇을 보일지 — 후보 넷 (낱말은 정해 주십시오)

- **가. 막힌 까닭을 그대로 말하는 띠**
  「오늘 이 계정이 쓴 AI 사용량이 상한에 닿았습니다 — 오늘 N회 · M토큰 / 상한 600만.
  자정에 풀립니다.」 지금 서버가 주는 `budget`에 필요한 값이 다 들어 있습니다.
- **나. 미리 알리기.** `budget.level`이 이미 `ok` / `warn`(0.7) / `blocked` 셋으로 계산됩니다.
  `warn`이면 「오늘 상한의 70%를 썼습니다」를 한 줄로.
- **다. 버튼에 까닭 달기.** 갈색 주 버튼에 `guard()`로 이유를 다는 통로가 이미 있습니다
  (「처리 중이 아닌 이유로 버튼을 회색으로 막지 않는다」 규칙과 같은 자리).
- **라. 관리자 화면에 「계정 하루 상한」 칸**과 회원별 표에 오늘 사용량.

돈은 막아야 하는 것이라 대원칙 ②의 예외가 맞습니다. 다만 **막되 왜 막혔는지는 화면에 남깁니다** —
지금은 그 부분이 빠져 있습니다.

## 5. 사업계획서 한 편에 얼마가 드나

**실측이 아니라 코드에서 낸 어림입니다.** 실제 값은 D1에 이미 쌓여 있고, 아래 「실측하는 법」으로 뽑습니다.

### 한 편의 호출 차례

1. `master` 한 번 — 입력에 공고 원문 + 직접자료 + 설계도 + 실행계약서 + 기관 확인정보가 모두 들어갑니다. 출력 상한 12,000
2. `draftPart` 묶음마다 한 번(보통 4~6번) — 공고 원문은 다시 보내지 않고 마스터 설계를 다시 보냅니다. 출력 상한 7,000
3. 고르면 더: `preciseReview` 8,000 · `patchSections` 10,000 · `coaching:start` 12,000 · `finalize` 9,000

### 어림 (입력 $5 · 출력 $30 per Mtok, 1,400원/$)

| | 토큰 | USD | 원 |
|---|---|---|---|
| 출력 (12,000 + 5×7,000 = 47,000) | 47,000 | $1.41 | 약 2,000원 |
| 입력 (공고·자료 크기에 따라 12만~32만) | 120,000~320,000 | $0.60~1.60 | 약 800~2,200원 |
| **한 편 합계 (설계 + 본문)** | | **$2.0~3.0** | **약 2,800~4,200원** |
| 검증·코칭까지 한 바퀴 더 | | +$0.5~1.5 | +700~2,100원 |
| 다시 만들기·수정을 여러 번 | | | 1만 원대까지 |
| **한 건 상한에서 멈추는 지점** | 200만 | **$20** | **약 28,000원** |

**짧게 답하면 한 편에 3천~5천 원, 검증까지 돌리면 5천~7천 원, 아무리 굴려도 계획서 한 건은 28,000원에서 멈춥니다.**

**믿을 만한 정도.** 출력 쪽은 코드가 상한을 정해 두어 거의 정확합니다.
입력 쪽이 어림인데, 공고 원문이 크면(코드 허용치는 18만 자) 입력만으로 한 편이 $1 넘게 더 붙습니다.
캐시가 걸리면 입력 단가가 1/10($0.5)이 되어 더 싸지지만, 캐시가 걸릴지는 앱이 정하지 못합니다.

### 실측하는 법 (제 계정으로는 Cloudflare 인증이 되지 않습니다)

터미널에서 이 한 줄이면 계획서별 실제 값이 나옵니다.

```
npx wrangler d1 execute ms12-proposal-archive --remote --command "SELECT proposal_id, COUNT(*) calls, SUM(input_tokens) inp, SUM(cached_input_tokens) cached, SUM(output_tokens) outp, SUM(cost_micro)/1000000.0 usd FROM ai_usage_events WHERE proposal_id != '' GROUP BY proposal_id ORDER BY usd DESC LIMIT 20"
```

**2026-08-19 이전 기록은 비용이 0으로 나옵니다**(단가를 그날 넣었습니다). 그 기간은 비용 대신
토큰으로 보고 `입력×5 + 출력×30 ÷ 1,000,000`으로 손으로 환산하면 됩니다.
