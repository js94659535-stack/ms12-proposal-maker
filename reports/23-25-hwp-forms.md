# [23-25] 손에 있는 .hwp 배분신청서로 서식 구조 확인

조사 완료 · 고치지 않음 · 배포 없음

## 먼저 — 파일 수를 바로잡습니다

`Desktop\MS12-E2E-결과\계획서 예시\`에는 **`.hwp` 하나와 `.pdf` 하나**뿐입니다.
23-24에서 「여덟 개」라고 적은 것은 제가 **바로가기(`.lnk`)를 파일로 세었기** 때문입니다.
바로가기를 따라가니 실물 `.hwp` **여섯**이 다른 폴더에 있습니다.

| 파일 | 어디 |
|---|---|
| 1. 프로그램(성과중심형) 배분신청서 (동가지역아동센터).hwp | `Documents\카카오톡 받은 파일` |
| **2023년복권기금방학프로그램배분신청서.hwp** | `Downloads` |
| 2026년 … 돌봄강화 … (벧엘, 진로ai동화)최종(마인드강사포함).hwp | `계획서 예시` · 카카오톡 |
| 2026년 … 돌봄강화 … (벧엘, 진로ai동화)최종.hwp | 카카오톡 |
| 프로그램 산출중심형 배분신청서 - 마인아동센터(최종).hwp | `Desktop\MS12-E2E-결과` |
| 프로그램 산출중심형 배분신청서 - 수완아동센터(최종).hwp | 카카오톡 |

**둘을 열었습니다** — 성격이 다른 두 서식입니다.

- **가** = 2026년 돌봄강화 (벧엘, 진로ai동화) — 49,664바이트
- **나** = 2023년 복권기금 방학프로그램 — 189,440바이트

## ⑴ 형식 — **진짜 `.hwp`(5.0)입니다**

둘 다 앞머리가 **`d0 cf 11 e0 a1 b1 1a e1`** — CFB(OLE2 복합 문서)입니다.
이름만 `.hwp`인 ZIP(`50 4b 03 04`)도 아니고 XML도 아닙니다.

**쓰기 쪽 갈림길의 답이 나왔습니다 — 이 기관 서식은 `.hwpx`가 아니라 `.hwp`입니다.**
23-23에서 「HWPX면 부품이 다 있다」고 했던 쉬운 길은 **이 파일들에는 해당하지 않습니다.**
(다만 이 여섯은 모두 **작성된 결과물**입니다. 기관이 배포하는 **빈 표준양식**이 `.hwp`인지
`.hwpx`인지는 여전히 그 ZIP을 열어야 확정됩니다.)

## ⑵ 이 저장소 읽기 코드로 — **둘 다 열립니다**

| | 가 | 나 |
|---|---|---|
| 글자 | 6,558자 | 3,214자 |
| 표 | **10개** | **7개** |

**표는 개수만 옵니다.** `extractHwpDocument()`가 돌려주는 것은 `{ text, tables }` 둘뿐이고,
**칸 이름도 좌표도 없습니다.**

**다만 줄 수준으로는 표의 머리글이 보입니다.** 본문에 **탭으로 구분되어** 들어옵니다.

```
세부 사업명	활동 내용(수행방법)	산출목표
기간  주요 내용	7월	8월	9월	10월	11월	12월

목	세목	세세목	계	산출근거	예산조달 계획
```

**이것이 23-23에서 「표를 안 읽는다」고 한 것보다 한 걸음 나은 상태입니다** — 구조는 없지만
**칸 이름은 글자로 남아 있습니다.** 다만 그것을 표로 다시 세우는 코드는 없습니다.

### 걸림률 87%가 실제 성능이 아닌 까닭 셋

1. **「사업명」이 둘 다 안 걸립니다.** `OUTLINE_MATCH`에 **사업명·제목 갈래가 없습니다.**
   서식의 **첫 칸**이고 심사자가 가장 먼저 보는 칸입니다.
2. **`programs`에 둘씩 겹쳐 붙습니다.** 두 서식 모두 「사업내용 및 추진방법」과
   「사업내용 및 방법」을 따로 묻는데 우리 쪽은 `programs` 하나뿐입니다.
   `fillFormLayout`은 첫 자리에만 넣고 둘째는 **`SHARED`(「앞 항목에 함께 썼습니다.
   이 항목에 맞춰 나눠 적어 주세요」)**로 비웁니다 — **사람이 손으로 나눠야 합니다.**
3. **우리 10항목 중 넷은 이 서식에 자리가 없습니다** — `purpose` · `goals` · `indicators` ·
   `outcomes`. 「서식 외 작성 내용」으로 뒤에 붙습니다.

**가 기준으로 서식 8칸 중 서로 다른 우리 항목이 실제로 들어가는 칸은 여섯입니다.**
한 칸은 못 붙고(사업명), 한 칸은 앞 칸과 겹칩니다.

## ⑷ 분량 표기 — **둘 다 0개**

`「N자 이내」`·`「N쪽 이내」`를 찾는 정규식으로 훑었더니 **한 줄도 없습니다.**

대신 **금액 한도**가 있습니다 — 「방학프로그램 600만원 이내, 노후기기 수리·렌탈 등 300만원 이내」.
글자·쪽 제한 대신 **표 칸 크기로 분량을 정하는 서식**으로 보입니다.
그렇다면 `form-spec.js`의 `CHAR_LIMIT`·`PAGE_LIMIT`은 **이 기관 서식에서는 쓸 일이 없습니다.**
(빈 표준양식에 작성요령이 붙어 있으면 거기 적혀 있을 수 있습니다 — 확정하려면 그 ZIP이 필요합니다.)

## ★ 채워진 결과물이라 빈 서식과 다른 점

| 무엇 | 채워진 것(지금 본 것) | 빈 서식이면 |
|---|---|---|
| 항목 이름 줄 | **남아 있음**(`1. 사업명`, `2. 사업 필요성` …) | 같을 것 — 항목 추출에는 지장 없음 |
| 안내문 | 답과 **한 줄에 섞여** 들어옴 (`• 참여자는 누구이며, 몇 명입니까? 참여 대상 : …`) | 안내문만 남음 — **오히려 읽기 쉬움** |
| 표 머리글 | 남아 있음 | 같을 것 |
| 표 안 내용 | 답이 들어차 있음 | 비어 있음 — **빈 칸의 개수·크기를 볼 수 있음** |
| 문서 종류 자동 판정 | **가에서 틀림** — 「예산 편성 기준」(24점 대 공모신청서 22점, confidence low). 채워진 예산 표 낱말에 끌렸다 | 안 틀릴 가능성이 큼 |
| 분량 표기 | 없음 | **작성요령이 따로 있으면 거기 있을 수 있음** |

**가장 크게 다를 곳은 「빈 칸이 몇 개이고 어디인가」입니다.** 채워진 문서에서는
답이 칸을 메우고 있어 **칸의 경계를 볼 수 없습니다.** 서식을 채우려면 그 경계가 필요합니다.
