## 확인된 핵심 결과

- 공고문 붙여넣기 → 마스터 설계 → 적응형 설계질문 → 전체 계획서 작성 → 수정 요청 → 확정값 반영 최종본 → 계획서보관함 저장·복구 → 검증 → 수정안 → 재검증 → 최종본 승인까지 한 흐름으로 이어진다.
- AI 작업 진행시간(`경과시간 MM:SS`)과 완료 표시(`✓ … 완료`)가 마스터·작성·수정·확정값·검증 전 구간에서 나타난다.
- 지정한 범위만 다시 쓰는 수정 요청이 다른 문단을 건드리지 않고, 이전 버전 본문이 그대로 보존된다.
- 확정값은 목표 문단에 배치되며, 확정 수치가 사라지는 수정안은 `확인필요` 등급으로 막힌다.
- 계획서보관함 저장 후 다시 열면 본문과 버전 이력이 동일하게 복구된다(CASE 2: 본문 10개·버전 3개).
- 검토 대상 버전이 고정되고 회차 비교(해결·잔여·신규)와 검토 이력이 누적된다.

## E2E로 찾아 수정한 결함

배포 커밋 `4eae985`에 포함된 8건.

1. 검토 제출 시 검증 화면으로 이동하지 않음
2. 검증 진행 중 경과시간이 끊기고 시작 시점에 완료 표시가 나옴
3. 단계 이동으로 끝나는 작업이 완료 배너를 건너뜀
4. 실패한 마스터 설계가 완료로 표시됨
5. 첫 완성본(V1)이 버전 이력에 기록되지 않음
6. 확정값 반영이 계획서 전체를 전송해 엣지 502 발생
7. 문제별 수정 요청이 계획서 전체를 전송해 엣지 502 발생
8. 공고문을 붙여넣기만 하면 선정 논리가 만들어지지 않음

추가로 E2E 하네스 자체의 오류 1건(`$` → `$$`)이 있었고, CASE 1·3에서 `보관 목록 조회 0건`으로 보이던 항목은 앱 결함이 아니라 이 오타 때문이었다.
