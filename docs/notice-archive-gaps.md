# 공고보관함 — 표에서 누를 수 있는 것들 (2026-08-19 조사)

사용자가 **「사업명을 눌렀더니 1단계로 돌아왔다」**고 했다.
실제로는 이동하지 않는다. 왜 그렇게 느끼는지가 이 문서의 내용이다.

조사만 했고 고치지 않았다. **크기: 중간. 우선순위: 첨부 키 저장 다음.**

---

## 표에서 누를 수 있는 것 열 가지

| 누르는 것 | 하는 일 | 화면 이동 |
|---|---|---|
| 행 체크박스 | `selected`에 담는다. 쓰임은 「선택 삭제」 하나뿐 | 없음 |
| 헤더 체크박스 | **지금 쪽에 보이는 행만** 전체 선택 | 없음 |
| **사업명** | 상세 행 펼침·접힘 (`data-archive-detail`) | **없음** |
| 상태 드롭다운 | 여덟 상태 중 하나로 저장(`setArchiveLink`) | 없음 |
| 기관 매칭 | 기관 고르는 줄 펼침 → 체크박스로 연결 저장 | 없음 |
| 삭제(행) | 그 한 건만 숨김. 확인 창 뜸 | 없음 |
| 펼친 뒤 「공고 상세」 | 목록에 넣고 이동 + `previewOfficialNotice` 실행 | 2단계 |
| 펼친 뒤 「공고 확인」 | 목록에 넣고 이동 | 2단계 |
| (우클릭) 6단계 메뉴 | 고른 단계로 이동 + 기관 선택 | 고른 단계 |
| (우클릭) 원문 바로가기 | 공식 사이트 새 창 | 외부 |

---

## 다섯 가지 문제

**1. 사업명 클릭이 이동이 아니라 펼침이다.**
`data-archive-detail`은 `expandedKey`만 토글한다. 그런데 `setState`로 화면 전체가 다시 그려지고,
펼침이 화면 아래쪽에서 일어나면 **스크롤이 위로 튀어** 1단계 상단이 보인다.
**「1단계로 돌아왔다」로 읽히는 것이 이 때문이다.** 눌렀는데 이동은 없고 화면만 다시 그려지니
무슨 일이 일어났는지 알 수 없다.

**2. 「이 공고로 작업하러 가기」가 두 겹 안에 있다.**
사업명을 눌러 펼치고, 거기 나오는 두 버튼 중 하나를 다시 눌러야 한다.
표에서 가장 자주 하고 싶은 일이 가장 깊이 있다.

**3. 상태에 맞는 단계로 가는 길은 우클릭 메뉴에만 있다.**
`useArchivedNotice`와 `viewArchivedNotice`는 **상태를 보지 않는다.**
계획서를 어디까지 썼든 무조건 `navigateToStep(1)` — 2단계로 보낸다.
**상태가 「제출준비」인 공고도 2단계로 간다.**
상태에 맞는 곳으로 가려면 행을 **우클릭**(모바일은 길게 누르기)해 6단계 메뉴를 열어야 하고,
그 메뉴는 `startArchiveWork(key, step, applicantId)`로 기관까지 골라 준다.
**기능은 이미 있는데 아무도 못 찾는 자리에 있다.**

**4. 「공고 확인」과 「공고 상세」가 사실상 같은 일이다.**
둘 다 그 공고를 임시 목록에 넣고 2단계로 간다. 차이는 「공고 상세」가 이어서
`previewOfficialNotice`까지 부른다는 것 하나뿐이고, 도착지도 같고 알림 문구만 다르다.

**5. 삭제가 두 곳에 있고 둘 다 이름이 틀렸다.**
행의 「삭제」와 체크박스 + 「선택 삭제」가 **같은 `hideArchivedNotices`**를 부른다.
한 건이냐 여러 건이냐만 다르다.
그리고 **DB에서 지우지 않는다 — 이 브라우저에서만 숨긴다.**
`state.archiveHiddenNotices`는 `localStorage`에만 있어 **다른 기기에서는 다시 보인다.**
개별 복구도 없다(`#archive-restore-hidden`으로 전부 되돌리기만 된다).
진짜 삭제(`DELETE FROM archived_notices`)는 관리자 화면에만 있다.

---

## 곁가지 — 체크박스가 무엇을 위한 것인지 화면이 말하지 않는다

`aria-label="행 선택"`뿐이고, 그 선택으로 할 수 있는 일이 삭제 하나라는 사실이 어디에도 없다.
「선택 삭제」 버튼은 표 위쪽에 있어 아래쪽 행을 체크할 때는 화면 밖이다.
일괄 상태 변경도, 일괄 기관 연결도, 일괄 내보내기도 없다.

---

## 순서

**첫째, 첨부 키 저장이 먼저다.** 지금 보관 공고의 첨부에는 `{name, fileType}`만 있어
나중에 다시 내려받을 방법이 없다(`docs/`의 다른 기록과 `functions/api/notices.js` 참고).
그것이 「보관」의 뜻을 절반 비우고 있어 이 문서의 어느 항목보다 크다.

**둘째가 이 문서다.** 크기는 중간이고, 손대는 것은 화면과 이동 경로다.
새 저장소도 새 API도 필요 없다 — **이미 있는 `startArchiveWork`를 보이는 자리로 올리고,
겹치는 두 버튼을 하나로 줄이고, 삭제의 이름을 사실대로 고치는 일**이다.
