## 2. 이 프로젝트의 대원칙

코드 곳곳 주석에 적혀 있고, 이틀간 이것으로 여러 결정을 내렸다.

**① 지어내지 않는다**
확인되지 않은 값은 `[확인 필요]`로 남긴다. 빈칸은 잘못이 아니고 틀린 값이 잘못이다.

**② 막지 말고 기록한다**
잘림·유출·오류를 차단하지 말고 기록해서 보이게 한다.

**③ 한 곳에서만 나오게 한다**
이름·문구·상수·판정을 여러 곳에 적지 않는다. 어긋나면 화면과 실제가 달라진다.

**④ 재보기 전에 정하지 않는다**
이틀간 측정값이 여러 번 뒤집혔다. 표본 하나로 상한을 정하지 않는다.

**⑤ 낱말 목록을 늘리지 않는다**
「이 낱말도 넣자」가 반복되면 쓰레기통이 된다. 빈도·구조 같은 다른 근거를 찾는다.

**⑥ 두 가지를 한 번에 바꾸지 않는다**
무엇 때문에 달라졌는지 모르게 된다.

## 3. 이틀간 가장 많이 나온 문제

**「기능은 있는데 그 사실이 안 보이거나, 판정이 엉뚱한 것을 본다」**

| 증상 | 실제 원인 |
|---|---|
| 잘렸는데 성공으로 기록 | 검사는 했는데 순서가 반대 |
| 서식 미인식이 화면에 없음 | 값을 계산해 놓고 안 올림 |
| ZIP 「지원 안 함」 안내 | 푸는 코드가 이미 있었음 |
| 「받기」가 반응 없음 | 막힌 이유를 화면 밖에 버림 |
| 다 쓴 계획서가 「0묶음」 | 새길에서 진행 기록을 안 남김 |
| 질문 분류가 틀림 | 성격 대신 출처를 봄 |
| 연혁에서 0건 | 규칙 27개가 그 경로에서만 꺼져 있었음 |
| 접기가 안 먹음 | 펼침 기억이 새로고침으로도 안 지워짐 |
| 화살표가 안 보임 | 붙을 자리(클래스)가 없었음 |
| 대상·강점이 비어 있음 | 함수는 멀쩡한데 부르는 자리가 세 사건에만 매여 있었음 |

**새로 만드는 것보다 이미 있는 것을 잇거나 보이게 한 일이 훨씬 많았다.**

## 4. 8/21에 한 일

**HWP 표에서 실적 뽑기 — 0건 → 99건**

HWP 본문 파서가 표 칸마다 한 줄로 만들어 행 개념이 사라졌다. 레코드에 행·칸 번호가 이미 있어서 그걸 읽으니 99행이 복원됐다.

그리고 「사업·프로그램으로 끝나야 실적」이라는 조건 때문에 「개별상담」·「학교폭력 예방교육」이 통째로 빠졌다. **낱말 목록을 늘리는 대신** 「한 행에 연도·발주기관·사업명이 함께 있으면 끝말과 무관하게 실적」으로 근거를 바꿨다.

**규칙 27개가 꺼져 있던 것**

`includeNarrative`가 기본 꺼짐이라 사용자가 서류를 올리는 경로에서만 표·서술 규칙이 안 돌았다. 나중에 만든 수리가 그 옵션 안에 갇혀 있었다. **기본값을 켬으로 뒤집었다.**

**공고 관련 실적만 골라 보내기 — 10,337자 → 1,255자**

기관 정보를 다 보내면 매 호출마다 실렸다. 공고와 겹치는 것만 내용까지 싣고 나머지는 건수만 알린다.

**공고에 따라 다르게 나온다** (실측)

| 공고 | 겹치는 실적 |
|---|---|
| 금융취약 중장년·노인 | 1건 |
| 아동·청소년 진로학습 | 14건 |
| 장성 돌봄 | 10건 |

## 5. 8/22에 한 일

### 화면 정리 — 이날의 큰 줄기

아침에 사용자가 **「너무 어마어마해서 엄두를 못 내겠다」**, **「다 치우고 새로 만들고 싶다」**고 했다. 세어보니 이랬다.

```
누를 수 있는 것        436개
반드시 눌러야 하는 것    2개
```

**고친 것**

| | 전 | 후 |
|---|---|---|
| 갈색 버튼 | 6개 | **1개 (맨 위 띠 고정)** |
| 다음 할 일 | 안 보임 | **띠 + 초록 + 화살표** |
| 실적 96건 | 네 곳에서 펼쳐짐 | 연도별 접힘 |
| 빈 입력칸 | 9구역 펼침 | 지움 |
| 기관 카드 | 버튼 4개 | 한 줄 |
| 저장 | 버튼 눌러야 | **자동** |
| 층 구분 | 없음 | 대·중·소 색으로 |

### 색 규칙 (지금 이것이 규칙이다)

| 색 | 뜻 |
|---|---|
| **초록** `#03C75A` | 지금 여기부터 하세요 — 화면에 하나 |
| **갈색** `#8c5a33` | 이 화면에서 할 수 있는 일 — 여러 개 가능 |
| **--navy** `#3f2e22` | 층 (대단원 배경) |

층 색 넷: `--fold-0` 대단원(navy·흰 글자) → `--fold-1` 중단원 → `--fold-2` 소단원 → `--fold-3` 소소단원(흰색). 바탕은 흰색.

**시험이 이 규칙을 지킨다.** 갈색으로 다음 할 일을 말하거나, 초록이 둘 이상이거나, 층 규칙에 초록·갈색이 들어오면 실패한다.

### 기관 정보 흐름

```
기관 만들기 → 서류 올리기 → 입력 후보 → 일괄 반영 → 모두 확인 → 계획서에 실림
                                          (확인 필요)   (확인됨)    (공고와 겹치는 것만)
```

**관문이 둘이다.** 반영해야 기관 정보가 되고, 확인해야 계획서로 간다.

### OCR (8/22 완성)

**`gpt-5.6-sol`이 이미지를 읽는다.** 스캔본 사업자등록증에서 아홉 항목을 정확히 뽑았다.

| | |
|---|---|
| 방법 | 기존 OpenAI 호출에 이미지를 얹음. 외부 벤더 없음 |
| 폭 | 1600px · JPEG80 (본문 382KB, 상한 750KB 안) |
| 장수 | 한 번에 세 장 |

**한 편의 값은 숫자 하나로 적을 수 없다.**
**한 번 깨끗하게 도는 값**과 **한 편이 끝날 때까지의 값**이 다르다 —
그 차이가 다시 만들기·검증 여러 바퀴·항목 재작성·실패한 호출이다.
실패해도 토큰은 청구되고 기록에 `ok=0`으로 남는다.

- 보통 한 편: **약 1,300원** (18건 실측 평균 1,322원)
- 손이 많이 간 한 편: **약 4,800원** (실측 최대 4,774원 · 호출 21회)

### 첫 판에서 틀렸던 것 셋

1. **「계획서 한 편 약 4,000원」** — 토큰 단가로 셈한 추정치인데 「추정」이라 적혀 있지 않아
   **실측처럼 읽혔다.** 다시 재 보니 깨끗한 한 번은 800~2,100원이고 실제로 가장 많이 쓴 계획서는
   4,774원이었다. **실측 평균은 1,322원**이라 4,000원은 보통 한 편의 세 배쯤이다.
   값보다 더 나빴던 것은 **무엇을 세는 숫자인지가 없던 것**이다 — 한 번 도는 값인지,
   손이 많이 간 한 편의 값인지.
   (23-16 첫 판이 「4,000원은 2~5배 높다」고 한 것도 틀렸다. 같은 병이다 — 이번엔 실측을 안 보고
   코드에서만 셌다.)
2. **「짧은 대화 1회 약 200원」** — **그런 자리가 코드에 없다.** 이 앱에 대화형 호출은 없고,
   OpenAI를 부르는 파일은 `proposal.js` · `proposal-coaching.js` · `proposal-review.js` · `ocr.js`
   넷뿐이다. 가장 가까운 것이 운영자 점검용 `probe`(출력 200토큰, 약 9원)다.
   **없는 기능의 비용이 표에 있었다.**
3. **「프롬프트 캐싱을 아직 안 붙였다」** — 안 붙인 것이 아니라 **붙일 수 없는 구조였다.**
   캐시는 앞머리가 글자 단위로 같아야 하고 **1,024토큰**을 넘어야 걸리는데, 지금은 모든 프롬프트가
   **첫 7~18자 만에 변수로 들어간다.** 고정 지시문은 반대로 **꼬리**에 있다
   (`master` 958자 · `draftPart` 501자 · `draft` 1,365자가 마지막 변수 뒤).
   앞에 남는 고정 글자는 developer 메시지 450자(≈280토큰)뿐이라 문턱에 못 미친다.
   실측에서도 캐시된 입력이 2.9%뿐이다.
   **고칠 일은 「붙이기」가 아니라 「순서 뒤집기」다** — 고정 지시문을 앞으로 옮기면 지금 있는
   글자만으로 `draftPart` 앞머리가 9,335토큰이 되고, 묶음마다 약 7,800토큰이 1/10 단가로 넘어가
   한 편의 약 15%가 준다.

### 상한

계획서 한 건 **$20 · 200만 토큰**, 계정 하루 **600만 토큰**. `server/ai-usage.js`의 `budgetRefusal()`이
네 엔드포인트 모두에서 호출 **전에** 본다. **계정 하루에 돈 기준은 없다.**
막히면 403에 `capReached`가 실려 오는데 **화면에서 그것을 읽는 자리가 없어** 「AI 실패」로 보인다.

자세한 것과 실측 질의는 `reports/23-16-ai-cost.md`, 상한은 `reports/23-15.md`.

## 9. 확인 안 된 것

**브라우저로 눈으로 본 것은 사용자뿐이다.** 개발 쪽은 그려진 HTML과 숫자까지만 확인할 수 있다.

이틀간 **시험이 통과했는데 화면에서 안 되는 일이 여러 번** 있었다.
- `querySelector`가 `null`을 돌려주고 `?.`가 조용히 삼킴
- 시험이 「코드에 있다」만 보고 「그 자리가 그 화면에 있나」는 안 봄
- 시험 자료가 이상적인 형식이라 실제 문서와 달랐음

**화면을 건드린 변경은 반드시 실제로 눌러 봐야 한다.**
